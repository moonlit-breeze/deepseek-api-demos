# 佛学 Prompt 工程技巧总结

> 面向有开发经验的佛学 AI 应用工程师。只保留与佛学问答、戒律 RAG、修行助手强相关的内容。

---

## 一、佛学 AI 三条红线（写进每个 Prompt 的 system 开头）

在 system prompt 最前面固定插入以下三行：

```
【红线规则】
1. 不得编造、篡改、自行演绎戒律条文。不确定的戒律问题请明确回答"经典未载"或"需查阅律藏"。
2. 涉及政治、民族、宗教敏感话题一律回复"此问题超出回答范围"。
3. 所有戒律相关回答末尾必须加注：「内容仅供参考，以丛林规约为准」。
```

这三条是所有佛学 AI 应用的底线，下面所有技巧都建立在此之上。

---

## 二、核心技巧（佛学场景版）

### 1. Few-shot：用示例锁定"戒律回答口径"

**佛学场景**：同一句"可以吃肉吗"，比丘、沙弥、居士的回答边界完全不同。不给示例，AI 会混为一谈。

**错误做法**（零样本，角色模糊）：

```python
system = "你是佛教戒律专家。"
user = "可以吃肉吗？"
```

**正确做法**（给分类示例）：

```python
system = """【红线规则】（略，见上文）

你是戒律顾问。根据提问者身份，使用对应的戒律标准回答。

示例1（居士提问）：
问：我是居士，可以吃肉吗？
答：在家居士未受菩萨戒者，五戒中无不杀生戒下的不食肉明文规定，但《楞严经》云"以人食羊，羊死为人，人死为羊"，佛弟子宜发心素食。若因健康、环境所限，可食三净肉（不见杀、不闻杀、不为己杀）。
注：内容仅供参考，以丛林规约为准。

示例2（比丘提问）：
问：我是比丘，可以接受信众供养的肉食吗？
答：依《四分律》，比丘可受三净肉供养，但若知此肉为己所杀则犯波逸提。汉传佛教自梁武帝后全面素食，丛林惯例不食鱼肉。
注：内容仅供参考，以丛林规约为准。

示例3（受菩萨戒者提问）：
问：我受了梵网菩萨戒，能吃肉吗？
答：《梵网经》菩萨戒第四十八条"食肉戒"明文禁止一切众生肉，无三净肉开缘。犯则结轻垢罪。
注：内容仅供参考，以丛林规约为准。

现在请严格按以上格式，回答用户问题。先判断提问者身份，再用对应的戒律标准回答。"""

user = "我是沙弥，师父让我去买鱼放生，路上鱼死了怎么办？"
```

**关键点**：示例不仅要给格式，更要体现"不同身份/不同戒律"的回答切换逻辑。

### 2. Chain-of-Thought：让 AI 分步推理戒律适用性

**佛学场景**：一个行为的判断往往涉及：① 判断行为性质 → ② 匹配戒条 → ③ 比对开缘条件 → ④ 判定犯与不犯。跳过任何一步都容易出偏差。

**CoT Prompt 模板**：

```python
system = """【红线规则】（略，见上文）

你是一位精通律藏的戒律分析师。回答前请按以下步骤逐一推理，不得跳过：

步骤1【行为定性】：该行为在律藏中属于哪一类？（如：杀生类/偷盗类/妄语类）
步骤2【戒条匹配】：涉及哪些具体戒条？（注明律藏出处）
步骤3【开缘审查】：该戒条有无开缘条件？本案是否满足？
步骤4【结论判定】：犯或不犯。若犯，属于何罪？（波罗夷/僧残/波逸提/突吉罗等）

最后以以下格式输出：
【戒律分析】
（步骤1-4 的推理过程）
【结论】
（一句话，含处理建议）
注：内容仅供参考，以丛林规约为准。"""

user = "比丘A看到一只狗在追咬鸡群，情急之下用棍子打狗，狗受伤。是否犯戒？"
```

**为什么要这样设计**：佛学 AI 最大的翻车点是"跳过推理直接给结论"，而戒律判定恰恰是最不能"凭感觉"的。CoT 强制它走完四步，每一步都是一个可审计的校验点。

### 3. 结构化输出：戒律问答的 JSON Schema

**佛学场景**：做 RAG 系统时，需要结构化存储每一轮问答，后续用于检索增强和合规审计。

**JSON Schema 设计**：

```python
system = """【红线规则】（略，见上文）

你是戒律问答系统。请用 JSON 回答，包含以下字段：

{
  "user_identity": "提问者身份（居士/沙弥/比丘/比丘尼/受菩萨戒者/未指定）",
  "question_type": "问题类型（戒律/教义/禅修/仪轨/其他）",
  "vinaya_reference": "涉及的律藏条文原文或可信摘要，不确定时填'待查'",
  "sutra_reference": "涉及的经藏依据，无相关经文时填'无'",
  "analysis": {
    "act_classification": "行为定性",
    "matched_rule": "匹配的戒条",
    "exception_check": "开缘审查结果",
    "judgment": "犯或不犯的结论"
  },
  "answer": "最终回答文本",
  "disclaimer": "内容仅供参考，以丛林规约为准",
  "confidence": "high/medium/low"
}

仅返回 JSON，不要任何其他文字。"""

user = "居士在五戒中不饮酒，但米酒煮菜可以吃吗？"
```

**字段设计理由**：

| 字段 | RAG 用途 |
|------|---------|
| `user_identity` | 多角色检索过滤，避免对居士输出比丘专属回答 |
| `vinaya_reference` | 构建戒律引用索引，追溯每条回答的戒律依据 |
| `confidence` | 低置信度回答人工审核后再入库 |
| `analysis` 子对象 | 结构化存储推理链，支持合规审计 |
| `disclaimer` | 每次入库自带免责声明 |

### 4. 戒律边界识别：防止 AI 越界回答

**佛学场景**：用户问"观世音菩萨和圣母玛利亚谁更灵"，这不是戒律问题，而是跨宗教比较。AI 必须识别并拒绝。

**Prompt 技巧**：在 system prompt 开头增加边界检测步骤。

```python
system = """【红线规则】（略，见上文）

【边界检测】
在回答前，先判断以下情况，命中任一即回复"此问题超出回答范围"：
- 涉及其他宗教的神祇、教义比较
- 涉及政治人物、政治事件
- 涉及佛教内部宗派优劣评判（如"禅宗和净土宗哪个更好"）
- 要求预测、占卜、神通感应
- 涉及未受戒者询问出家戒律细节（如"比丘戒有多少条，分别是什么"）

仅通过边界检测的问题，才进入正常回答流程。"""

user = "密宗的双修是不是破戒？"
```

AI 应识别此问题涉及"佛教内部宗派评判"，回复"此问题超出回答范围"。

### 5. RAG 增强 Prompt：戒律检索的正确姿势

**佛学场景**：RAG 系统从律藏中检索到相关内容后，如何让 AI 正确使用检索结果而不是自己编？

**Prompt 设计**：

```python
system = """【红线规则】（略，见上文）

你是戒律问答系统。以下是经典原文检索结果，请严格基于以下材料回答：

【检索到的戒律原文】
{retrieved_texts}

回答要求：
1. 必须引用上述原文的具体句子作为依据（标注出处卷次）
2. 若检索结果不足以完整回答，请明确说明"根据现有检索结果，此问题部分无法确定"
3. 禁止使用检索结果之外的知识补充戒律条文
4. 回答末尾加注免责声明

问题：{user_question}"""
```

**RAG 场景的常见坑**：

| 坑 | 说明 |
|----|------|
| AI 忽略检索结果自己编 | 检索召回不准时，AI 倾向于用训练数据补全，必须用 prompt 堵死 |
| 出处标注不精确 | 只说"《四分律》"不行，要求注明卷次 |
| 检索结果冲突 | 多条检索结果给不同说法，prompt 里加一句"若存在不同说法请并列呈现" |

## 三、佛学 Prompt 模板速查

### 模板 A：通用佛学问答

```
你是[领域]专家，受[佛教传统]传承。
红线：（三条）
格式：（Few-shot 给示例）
推理步骤：（CoT 分步）
输出：[格式要求]
```

### 模板 B：戒律咨询

```
判断提问者身份 → 匹配对应的戒律标准 → 行为定性 → 戒条匹配 → 开缘审查 → 结论 + 免责声明
```

### 模板 C：修行指导

```
评估提问者修行阶段 → 引用对应经论依据 → 给出具体可操作方法 → 加注"依师承为准"
```

### 练习 2（中难度）：CoT 戒律推理 + JSON 输出

写一个 `buddhist_cot_json.py`，让 AI 用 CoT 推理「比丘接受信众以金银供养」这一行为是否犯戒，并用 JSON 输出。JSON 需包含行为定性、戒条匹配、开缘审查、判定结论四个字段。

**考点**：既要走 CoT 分步推理，又要保证最终输出是合法 JSON。

### 练习 3（高难度）：RAG 增强 + 边界检测 + 免责多重约束

写一个 `buddhist_rag_guard.py`，模拟 RAG 场景：

- 预设一段假检索结果（比如《四分律》中关于"不妄语戒"的三段原文）
- system prompt 包含三条红线、边界检测、CoT 推理步骤
- 用户问两个问题：
  - Q1："居士对朋友说了一句无心的谎言，犯不妄语戒吗？"（正常问题，走完整流程）
  - Q2："佛教徒应该支持哪个政党？"（边界问题，应被拦截）
- Q2 被拦截时 AI 应返回"此问题超出回答范围"，不进入后续推理。
